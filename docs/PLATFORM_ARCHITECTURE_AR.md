# هندسة منصة روافد

الإصدار: 1.0  
الحالة: معيار معماري ملزم للصفحات الجديدة وإعادة تنظيم الصفحات الحالية

## 1. الهدف

تحويل المشروع من مجموعة صفحات كبيرة إلى منصة عربية مترابطة تقود المستخدم من السؤال إلى الفهم، ثم إلى الإجراء الآمن، ثم إلى المصدر والمنهج وحدود الاستخدام. لا تقاس جودة المنصة بعدد الصفحات وحده، بل بقدرة المستخدم ومحرك البحث والمراجع العلمي على فهم مكان الصفحة وعلاقتها ببقية المحتوى.

## 2. البوابات العليا

يجب أن يبقى التنقل العالمي محدودًا ومستقرًا:

1. ابدأ من هنا.
2. الموسوعة النفسية.
3. المقارنات.
4. المكتبة الأكاديمية.
5. الأدلة العملية.
6. ذوو الاحتياجات الخاصة والتربية الدامجة.
7. المجلة والأبحاث.
8. الأدوات ومسارات التعلم.
9. الثقة والمنهجية.

تظل الأقسام الأخرى متاحة داخل البوابة المناسبة أو دليل الأقسام، ولا تتحول الترويسة إلى قائمة تضم كل صفحة في الموقع.

## 3. طرق الوصول

### حسب نية المستخدم

- فهم حالة أو مصطلح.
- التمييز بين حالتين متشابهتين.
- ملاحظة علامات تستدعي تقييمًا مهنيًا.
- دعم شخص في المنزل أو المدرسة أو العمل.
- قراءة دليل علمي أو مراجعة بحثية.
- استخدام أداة تنظيمية غير تشخيصية.
- اختيار خدمة أو مختص والتحقق من الجودة.

### حسب الدور

- الشخص نفسه.
- الأسرة ومقدم الرعاية.
- المعلم والمدرسة.
- الطالب والباحث.
- المختص ومقدم الخدمة.
- المؤسسة والمانح والشريك.

### حسب المرحلة

- الوقاية والتثقيف.
- الملاحظة وجمع السياق.
- المسح الأولي المسؤول.
- التقييم المهني.
- التخطيط والدعم.
- قياس التقدم والمراجعة.
- الانتقال والاستقلال والمشاركة.

## 4. أنواع المحتوى

كل صفحة يجب أن تنتمي إلى نوع واحد أساسي، مع إمكان الارتباط بأنواع أخرى:

| النوع | الغرض |
|---|---|
| صفحة تعريف | تعريف المصطلح وحدوده والفروق الأساسية |
| صفحة علامات | وصف الأنماط والسياق والأثر دون تشخيص ذاتي |
| مقارنة | توضيح أوجه التشابه والاختلاف وما لا تحسمه المقارنة |
| دليل عملي | خطوات قابلة للتنفيذ والمتابعة ضمن حدود واضحة |
| مراجعة علمية | سؤال، منهج، عينة، نتائج، قيود، دلالة عملية، مصدر أصلي |
| مركز موضوعي | جمع المحتوى المرتبط في مسار واحد |
| أداة تفاعلية | تنظيم أو تعلم محلي مع خصوصية وحدود غير تشخيصية |
| صفحة حوكمة | المنهج والحقوق والتصحيح والخصوصية وحالة المراجعة |

## 5. العقد التحريري الإلزامي

يجب أن تحتوي الصفحة المعرفية الكاملة على:

1. عنوان واحد واضح يطابق نية البحث.
2. إجابة افتتاحية مباشرة لا تتجاوز فقرتين.
3. تعريف دقيق وحدود المصطلح.
4. ما الذي قد يختلط به.
5. العلامات أو المؤشرات مع السياق والمدة والأثر.
6. العوامل المحتملة دون اختزال سببي.
7. متى يلزم تقييم أو مساعدة عاجلة.
8. خطوات عملية تناسب الجمهور المستهدف.
9. ما لا يمكن استنتاجه من الصفحة.
10. مصادر أصلية أو مؤسسية قابلة للتحقق.
11. تاريخ النشر والمراجعة وحالة المراجعة.
12. روابط داخلية إلى المقارنة والدليل والمركز والمصدر المرتبط.

## 6. هرم المصادر

الأولوية حسب السؤال، لا حسب شهرة اسم المصدر فقط:

1. قوانين ومعايير وبيانات جهات رسمية دولية أو وطنية.
2. إرشادات مهنية رسمية محدثة.
3. مراجعات منهجية وتحليلات تلوية عالية الجودة.
4. تجارب ودراسات أصلية مناسبة للسؤال.
5. مراجع أكاديمية متخصصة.
6. مواد جامعية أو مؤسسية تعليمية موثوقة.
7. مصادر تفسيرية ثانوية عند الحاجة، مع عدم استخدامها لإثبات ادعاء أساسي إذا توفر الأصل.

لا تعد الإشارة إلى مصدر عالمي دليلًا على أن الصفحة معتمدة من الجهة أو راجعتها.

## 7. دورة حياة المحتوى

`idea → scoped → evidence-collected → drafted → scientific-check → safety-check → editorial-check → published → monitored → revised/withdrawn`

### الحالات

- `idea`: موضوع مقترح.
- `scoped`: سؤال وجمهور ونطاق محدد.
- `evidence-collected`: المصادر الأساسية محفوظة.
- `drafted`: مسودة كاملة.
- `scientific-check`: فحص الادعاءات والمراجع.
- `safety-check`: فحص التشخيص والدواء والأزمات والوصم والحقوق.
- `editorial-check`: اللغة والبنية والروابط وSEO والإتاحة.
- `published`: منشور مع تاريخ وحالة مراجعة.
- `monitored`: خاضع لفحص الروابط والحداثة والتصحيحات.
- `revised`: عُدّل مع سجل سبب وتاريخ.
- `withdrawn`: سُحب بسبب خطأ أو تقادم أو مشكلة حقوقية.

## 8. بوابات الجودة قبل النشر

لا تنشر الصفحة ما لم تجتز:

- صحة بنية HTML والعنوان الرئيسي.
- عنوان ووصف وCanonical وبيانات مشاركة.
- عدم وجود روابط داخلية مكسورة.
- ذكر المصادر الأصلية للمعلومات الجوهرية.
- عدم وجود ادعاء تشخيصي أو علاجي مطلق.
- توضيح الجمهور والحدود المهنية.
- تباين ولوحة مفاتيح ونص بديل مناسب.
- عدم استخدام لغة وصمية أو اختزال الشخص في الحالة.
- عدم نشر مادة اختبار محمية أو محتوى منسوخ.
- وجود صفحة تالية منطقية ضمن رحلة المستخدم.

## 9. الفهرسة والربط الداخلي

كل صفحة يجب أن ترتبط على الأقل بـ:

- الصفحة الأم أو المركز الموضوعي.
- صفحتين معرفيتين مرتبطتين.
- دليل عملي واحد عند وجود تطبيق مناسب.
- صفحة الثقة أو المنهج عند وجود ادعاء حساس.
- المصدر الأصلي في الصفحات البحثية.

تستخدم مسارات URL مستقرة باللغة الإنجليزية التقنية أو Slugs واضحة، بينما يبقى عنوان الصفحة ومحتواها عربيين. لا تغيّر الروابط المستقرة دون تحويل دائم.

## 10. القياس

المؤشرات الأساسية:

- نسبة الصفحات ذات مصادر أولية قابلة للتحقق.
- نسبة الصفحات المجتازة لبوابات الجودة.
- الروابط المكسورة ومدة إصلاحها.
- عمر آخر مراجعة للمحتوى الحساس.
- نجاح البحث الداخلي والوصول إلى النتيجة.
- انتقال المستخدم من التعريف إلى الدليل المناسب.
- الصفحات اليتيمة التي لا تستقبل روابط داخلية.
- تصحيحات ما بعد النشر وسببها وزمن تنفيذها.

لا تستخدم الزيارات وحدها بوصفها دليلًا على الجودة أو الأثر الصحي.

## 11. قاعدة التوسع

كل إضافة جديدة يجب أن تحسن واحدًا على الأقل من الآتي:

- تغطية فجوة معرفية حقيقية.
- الإجابة عن نية بحث غير مغطاة.
- ربط صفحات موجودة في مسار أوضح.
- تحديث دليل تغير أو تقادم.
- تقديم أداة آمنة أو مادة عملية مفيدة.
- تحسين الإتاحة أو الفهم أو قابلية التحقق.

يمنع إنشاء صفحات متقاربة لمجرد زيادة العدد أو الكلمات المفتاحية.
