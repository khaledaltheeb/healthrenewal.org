# سياسة استعادة النسخ الكاملة v1

ترتبط هذه الحزمة بـ Issue #158، وهدفها منع فقد المحتوى عند مقارنة النسخ الحالية بالنسخ القديمة والفروع وطلبات السحب والالتزامات.

## القاعدة الملزمة

1. لا يُحذف محتوى صالح ولا يُختصر أثناء الاستعادة.
2. لا تُحوّل الصفحة إلى redirect بوصفه بديلًا عن دمج محتواها.
3. تُجمع جميع النسخ المتاحة للمسار نفسه من Git refs والتاريخ الكامل.
4. تُقاس كل نسخة بالكلمات والبنية والعناوين والأقسام والروابط والمراجع وSchema وRTL والطباعة ومؤشرات القوالب الفارغة.
5. تُعتمد النسخة الأغنى والأشمل كأساس تحريري، لا بوصفها نسخة تُنسخ آليًا دون مراجعة.
6. تُدمج المعلومات الفريدة من النسخ الأخرى داخل الأساس بعد إزالة التكرار وحسم التعارض وفق المصدر الأوثق والأحدث.
7. يُوثق لكل صفحة: المسار، النسخ المقارنة، المقاييس، النسخة المقترحة كأساس، سبب الاختيار، وحالة الملف المحجوز.
8. أي تعديل فعلي للمحتوى يتم في PR منفصل أو دفعة صغيرة قابلة للمراجعة، ولا يُدمج قبل نجاح بوابات HTML والروابط وRTL والهاتف والطباعة وSchema.

## الملفات المحجوزة في هذه الدورة

لا تعدل حزمة الاستعادة هذه الملفات، وتكتفي بإظهارها في التقرير:

- `magazine/feed.xml`
- `magazine/index.html`
- ملفات إصلاح `BASE_PATH` التي يعمل عليها PR #1063:
  - `scripts/expand_v12_direct.py`
  - `scripts/complete_core_sections_v15.py`
  - `scripts/expand_v12_direct_legacy_v1.py`
  - `scripts/complete_core_sections_v15_legacy_v1.py`
  - `scripts/site_base_path_v1.py`

## المخرجات

يشغّل `scripts/audit_full_content_recovery_v1.py` فحصًا غير هدّام وينتج:

- `reports/full-content-recovery-v1/inventory.json`: سجل تفصيلي لكل صفحة ونسخها.
- `reports/full-content-recovery-v1/summary.md`: قائمة مرتبة بأقوى مرشحي الاستعادة.

تُرفع المخرجات كـ GitHub Actions artifact لمدة 30 يومًا. لا تُكتب النتائج المولدة تلقائيًا إلى فرع الإنتاج، كي لا تتضخم الفروقات ولا تُخلط نتائج التدقيق مع المحتوى المحرر.

## ترتيب التنفيذ بعد نجاح البوابة

1. مراجعة أعلى حالات `probable-placeholder-regression` و`probable-truncation-regression`.
2. حجز مجموعة صغيرة من المسارات غير المتعارضة عبر Issue #158.
3. استخراج النسخة الأساسية ومقارنة الأقسام والمراجع فقرة بفقرة.
4. دمج المعلومات الفريدة دون حذف أو اختصار.
5. توثيق النسخ والقرار داخل PR.
6. تشغيل جميع بوابات الموقع قبل تغيير حالة PR من Draft.
