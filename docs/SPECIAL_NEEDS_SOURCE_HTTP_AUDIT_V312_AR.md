# الفحص الشبكي لمراجع التوحد ومتلازمة داون — v312

## الهدف

تنفيذ فحص HTTP فعلي لجميع المراجع السبعة عشر، منفصل عن تدقيق البيانات والصيانة v310.

## السياسة

لا تُعامل كل استجابة غير ناجحة باعتبارها رابطًا مكسورًا؛ بعض المواقع الطبية والأكاديمية تمنع الروبوتات أو تحد معدل الطلبات.

### نتائج مانعة

- `404 Not Found` بعد طلب GET تأكيدي.
- `410 Gone` بعد طلب GET تأكيدي.
- التحويل من HTTPS إلى HTTP غير المشفر.

### ملاحظات غير مانعة لكنها تظهر في التقرير

- 401 أو 403 أو 405 أو 406 أو 429 وحالات منع الوصول الآلي.
- 451 عند وجود قيد قانوني أو جغرافي.
- أخطاء خادم 5xx.
- مهلة الاتصال أو DNS أو TLS أو فشل نقل مؤقت.
- حالة HTTP غير معتادة لا تثبت وحدها أن المرجع اختفى.

## طريقة الفحص

- يبدأ بطلب HEAD خفيف.
- ينتقل إلى GET محدود المدى عند عدم نجاح HEAD.
- يعيد GET مرة عند فشل النقل دون استجابة HTTP.
- يتبع التحويلات ويتحقق من بقاء الرابط النهائي على HTTPS.
- يستخدم أربعة عمال متوازيين وحدًا زمنيًا لكل طلب.

## التشغيل

- عند تعديل بيانات مراجع التوحد أو متلازمة داون أو كود المدقق.
- أسبوعيًا صباح كل اثنين عبر GitHub Actions.
- يدويًا من `workflow_dispatch`.

## المخرجات

ينتج ملفًا ديناميكيًا داخل أثر GitHub Actions:

`_audit/special-needs-condition-source-http-v312.json`

ويتضمن كل محاولة وطريقتها وحالة HTTP والرابط النهائي ونوع المحتوى والمدة والخطأ والتصنيف النهائي.

## حدود الادعاء

نجاح الفحص يعني أن المدقق لم يجد رابطًا مؤكد الانقطاع وفق السياسة وقت التشغيل. لا يعني ذلك مراجعة المحتوى السريري للصفحة الخارجية أو ضمان استمرار الرابط مستقبلًا.
