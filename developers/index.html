بوابة المطورين وواجهات البيانات الصحية المسؤولة

هذه البوابة نقطة البداية للمطورين والباحثين والمؤسسات التي تريد اكتشاف محتوى المنصة أو ربطه بخدمة أخرى. يسبق التنفيذ تحديد حالة الاستخدام والجمهور والحقول والمخاطر والحقوق. يُبنى التكامل على عقد OpenAPI ومخططات JSON وإصدارات معلنة، مع تحقق دفاعي وأمان وإتاحة وإسناد. لا يجوز تحويل المقالات أو نتائج الأدوات إلى تشخيص أو علاج أو قرار أهلية آلي يتجاوز المصدر والغرض المعلن.

اكتب الجمهور والمشكلة والمخرج والقرار الذي سيتأثر، وما الذي لن يفعله التكامل.

افتح العقد الحي

ولّد عميلًا أو تحققًا

اختبر حالات الفشل

حقول مفقودة، مهلة، معدل طلبات، استجابة فارغة، إصدار جديد، وترميز عربي.

اعرض المصدر والحدود

احتفظ بالرابط والإصدار وتاريخ الاسترجاع والإسناد وتنبيه المحتوى التثقيفي.

راقب وراجع

سجل الأخطاء دون بيانات حساسة، تابع التغييرات، واختبر التكامل دوريًا.

مثال استجابة دفاعية عامة

لا يفترض العميل أن جميع الحقول موجودة أو أن النص عربي دائمًا. يتحقق من نوع البيانات، يضع بديلًا عند غياب الوصف، يحتفظ بمعرف المورد والرابط، ويرفض استخدام درجة أو وسم حساس إذا لم يكن الغرض موثقًا.

{
  "data": [],
  "meta": {"version": "v1", "retrieved_at": "ISO-8601"},
  "links": {"self": "...", "next": null},
  "errors": []
}

هذا مثال تصميمي توضيحي، وليس ادعاءً بأن كل استجابة حية تستخدم هذه البنية. ملف OpenAPI المنشور هو المرجع الفعلي.

الإصدارات والتوافق والإهمال

إصدار رئيسي

تغيير قد يكسر العميل

حذف حقل أو تغيير معناه أو نوعه أو بنية المسار يحتاج إصدارًا رئيسيًا ومسار انتقال معلنًا.

تغيير متوافق

إضافة غير كاسرة

قد تضاف حقول اختيارية أو قيم جديدة. العميل الجيد يتجاهل ما لا يعرفه ولا يحصر القيم بلا خطة تحديث.

إهمال

تحذير قبل الإزالة

يُعلن المورد أو الحقل القديم، والبديل، والموعد المتوقع، وأثر الانتقال عندما تسمح البنية بذلك.

سجل تغييرات

ماذا تغير ولماذا؟

يحتاج المطور إلى وصف عملي للتغيير وتاريخ ومثال ترحيل، لا رقم إصدار فقط.

قواعد عميل متوافق

  • لا يعتمد ترتيب حقول JSON.
  • يتعامل مع حقول إضافية وقيم enum جديدة بأمان.
  • لا يفسر غياب الحقل كقيمة صفرية أو نفي سريري.
  • يثبت نسخة العقد في الاختبارات ويراقب النسخة الحية.
  • يملك مهلة واتصالًا قابلًا للإلغاء وإعادة محاولة محدودة مع backoff للطلبات الآمنة.
  • يمنع تكرار عملية غير قابلة للتكرار تلقائيًا دون idempotency مناسب.

نموذج الأخطاء وتجربة المستخدم

الفئةمثالسلوك التطبيق
طلب غير صالحمعامل ناقص أو صيغة غير صحيحة.اشرح الحقل المطلوب ولا تعِد المحاولة نفسها آليًا.
غير مصرح أو ممنوعاعتماد مفقود أو صلاحية غير كافية.لا تكشف تفاصيل أمنية، ووجه إلى مسار المصادقة أو الدعم.
غير موجودمعرف أو إصدار لم يعد متاحًا.اعرض بديلًا أو نتيجة فارغة موضحة، لا صفحة مكسورة صامتة.
معدل طلباتطلبات كثيرة خلال مدة قصيرة.احترم Retry-After إن وجد، وقلل التوازي واستخدم cache.
خطأ خادمفشل مؤقت أو اعتماد داخلي.إعادة محدودة للطلبات الآمنة ورسالة غير مخيفة للمستخدم.
مخطط غير متوقعنوع أو بنية لا تطابق العقد.فشل آمن، تسجيل تقني منقح، وتنبيه فريق التكامل.
لا تعرض رسالة خام للمستخدم. افصل بين رسالة إنسانية مختصرة وبيانات تشخيص تقنية منقحة. لا تسجل إجابات أو استعلامات صحية حساسة أو رموز اعتماد ضمن السجلات.

أمان API وفق المخاطر الواقعية

تفويض على مستوى الكائن

لا يكفي امتلاك معرف مورد. تحقق من حق المستخدم في الوصول إلى كل كائن، خصوصًا البيانات غير العامة.

مصادقة وإدارة جلسة

رموز قصيرة ومحدودة النطاق، تخزين آمن، تدوير وإلغاء، وعدم إرسال السر في الرابط.

تقليل كشف البيانات

أعد الحقول اللازمة فقط، وافصل الموارد العامة عن الخاصة، ولا تثق بأن العميل سيخفي الحقول الحساسة.

تحديد الموارد

حدود للحجم والصفحات والوقت والتوازي والملفات حتى لا يتحول الطلب الصحيح إلى استنزاف.

التحقق من المدخلات

قوائم سماح وأنواع وأطوال وحدود، ومنع تمرير المدخل مباشرة إلى استعلام أو قالب أو رابط داخلي.

جرد وإصدارات

اعرف كل مضيف ومسار وإصدار وتجربة، وأغلق النسخ القديمة والواجهات التجريبية غير المحمية.

تكاملات الطرف الثالث

تعامل مع استجاباتها كبيانات غير موثوقة، وحدد مهلة ومخططًا وقائمة وجهات مسموحة.

أسرار ومفاتيح

لا تُضمّن في المستودع أو المتصفح. استخدم مخزن أسرار وصلاحيات محدودة ومراقبة تسرب.

مراقبة واستجابة

أحداث أمنية قابلة للتتبع، تنبيه مناسب، وخطة إبطال مفاتيح وتصحيح وإخطار حسب الالتزام.

اختبار أمان قبل الإنتاج

  • اختبارات تفويض لكل مورد ودور ومستخدم.
  • منع الوصول بمعرف متوقع أو معدل يدويًا.
  • حدود حجم ووقت ومعدل واستعلامات معقدة.
  • فحص حقن وSSRF وتحويلات وروابط خارجية.
  • منع الأسرار والبيانات الصحية من السجلات ورسائل الخطأ.
  • تحديث التبعيات وفحصها مع سياسة استجابة للثغرات.
  • رؤوس نقل آمن وHTTPS وعدم خفض التحقق من الشهادة.
  • اختبار نسخ API القديمة والبيئات التجريبية أيضًا.

مبادئ إلزامية

  • جمع أقل قدر لازم، لا «قد نحتاجه لاحقًا».
  • فصل الهوية عن المحتوى متى أمكن.
  • تحديد مدة الاحتفاظ والحذف الآمن.
  • عدم بيع بيانات الصحة النفسية أو استخدامها لاستهداف إعلاني.
  • عدم إعادة تحديد الأفراد من مجموعات أو سجلات تبدو مجهولة.
  • شرح واضح للمستخدم قبل الجمع، لا سياسة غامضة بعده.

الإتاحة والتدويل واللغة العربية

واجهات قابلة للوحة المفاتيح

ترتيب تركيز منطقي، مؤشرات مرئية، وعناصر HTML أصلية قبل المكونات المعقدة.

قارئات الشاشة

عناوين وتسميات وأخطاء مرتبطة بالحقول وإعلانات تغير الحالة دون الاعتماد على الشكل.

تباين وحركة

تباين مناسب، عدم الاعتماد على اللون، واحترام تفضيل تقليل الحركة.

RTL وBidirectional

اختبر العربية مع أرقام وروابط وأكواد إنجليزية، ولا تعكس الكود أو المعرفات التقنية.

Unicode وترميز

UTF-8، تطبيع مدروس للبحث، وعدم تغيير النص الأصلي أو إسقاط التشكيل عشوائيًا.

تواريخ وأرقام

صيغة آلة ثابتة في API مثل ISO 8601، وعرض محلي في الواجهة دون فقد المنطقة الزمنية.

المعيار: تستهدف الواجهات العامة وتجارب المطور متطلبات WCAG 2.2 ذات الصلة، ولا تعتبر الإتاحة مرحلة لاحقة بعد اكتمال المنتج.

الإسناد والترخيص وسلامة إعادة الاستخدام

احتفظ بأصل الادعاء

الرابط إلى صفحة المنصة لا يستبدل المرجع العلمي الأصلي المدرج فيها عند نقل معلومة علمية.

اعرض تاريخ وإصدار

المحتوى الصحي يتغير؛ احفظ تاريخ الاسترجاع وآخر مراجعة أو إصدار إن توفر.

لا تحذف الحدود

عند إعادة العرض، لا تنقل التوصية وتزيل التحذير أو الجمهور أو درجة الدليل أو شرط الإحالة.

راجع الحقوق لكل مورد

وجود API لا يعني أن كل نص أو صورة أو أداة مرخصة لإعادة النشر الكامل.

قائمة جاهزية التكامل المؤسسي

  • حالة الاستخدام والجمهور والقرار والمخاطر موثقة.
  • ملف OpenAPI الحي قُرئ، والعميل يحقق المخطط ويتعامل مع التغيير.
  • اختبارات النجاح والفشل والمعدل والمهلة والترقيم والترميز موجودة.
  • نموذج تهديد واختبارات تفويض وأسرار وسجلات منقحة مكتملة.
  • تصنيف البيانات والغرض والاحتفاظ والحذف والمشاركة محددة.
  • الواجهة العربية وRTL ولوحة المفاتيح وقارئ الشاشة والتباين مختبرة.
  • الإسناد والترخيص وتاريخ المصدر وحدود المحتوى ظاهرة للمستخدم.
  • لا توجد توصية سريرية أو تصنيف عالي الأثر مشتق آليًا دون إطار مستقل.
  • مراقبة وأخطاء وتنبيه وخطة رجوع وإهمال إصدار موجودة.
  • مسؤول تقني ومسؤول محتوى وقناة تبليغ أمني وتصحيح محددون.

أسئلة شائعة

هل يمكن نسخ كل محتوى المنصة عبر API؟

لا يُفترض ذلك. راجع العقد والحقوق لكل مورد؛ توفر البيانات للاكتشاف أو التكامل لا يمنح تلقائيًا حق إعادة نشر كامل.

أي نسخة OpenAPI يجب أن يدعمها العميل؟

ابدأ بالنسخة المستخدمة في الملف الحي المنشور. لا تفترض أن أحدث نسخة من المواصفة هي نسخة العقد الفعلية.

هل يمكن استخدام البيانات لتدريب نموذج ذكاء اصطناعي؟

يلزم مراجعة الحقوق والغرض والخصوصية ومخاطر الاستنتاج وإعادة التحديد. لا تستخدم بيانات حساسة أو محمية أو تحول المحتوى إلى تشخيص آلي دون أساس مستقل.

كيف أبلغ عن ثغرة؟

استخدم قناة التواصل الرسمية مع وصف قابل لإعادة الإنتاج وأقل قدر من البيانات. لا تنشر بيانات أو تستغل الثغرة خارج ما يلزم للتحقق المسؤول.

هل API بديل عن المصدر العلمي؟

لا. API ينقل بيانات منظمة؛ الادعاء العلمي يعود إلى مرجعه الأصلي وسياقه وحدوده وتاريخ مراجعته.
