واجهة قراءة عامة وتكامل لا يعمل بلا إذن

تتيح الواجهة اكتشاف أقسام المنصة وقراءة المواصفة وكتالوج بيانات الدورات المخولة. جميع النقاط عامة وثابتة للقراءة، ولا تستقبل بيانات شخصية أو نتائج صحية أو ملفات دورات.

شرط استيراد الدورات

الوصول الشبكي معطل افتراضيًا. لا يُستورد أي feed إلا بعد تسجيل المزود، وتوثيق الإذن والترخيص، وتحديد النطاقات المسموح بها، وتفعيل المزود صراحة في بيئة البناء. تُنشر البيانات الوصفية والروابط الأصلية فقط؛ لا تُنسخ الفيديوهات أو الملفات أو الدروس أو الاختبارات.

النقاط المتاحة

GET /api/v1/platform.json

اسم المنصة والموارد وسياسة التكامل وروابط نقاط API.

عرض الاستجابة

GET /api/v1/openapi.json

مواصفة OpenAPI 3.1 للقراءة وتوليد العملاء والتحقق من العقد.

عرض المواصفة

GET /api/v1/courses.json

كتالوج البيانات الوصفية المستوردة من مزودين مخولين؛ يكون فارغًا بأمان عند غياب الإذن.

عرض الكتالوج

GET /api/v1/courses.schema.json

مخطط feed يفرض هوية مقدم الخدمة والإذن والحقوق والروابط الأصلية.

عرض مخطط التغذية

GET /api/v1/course-provider-registry.schema.json

مخطط سجل المزودين وحالات التفويض والتعليق والإلغاء والانتهاء وقائمة النطاقات.

عرض مخطط المزودين

GET /api/v1/courses.example.json

مثال توضيحي فقط؛ لا يمثل دورة حقيقية أو شراكة أو إذنًا قائمًا.

عرض المثال

مثال قراءة الكتالوج

fetch("https://khaledaltheeb.github.io/pterminology-site/api/v1/courses.json")
  .then(response => {
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return response.json();
  })
  .then(catalog => console.log(catalog.courseCount, catalog.courses))
  .catch(console.error);

قواعد الاستقرار والسلامة

  • الإصدار الرئيسي في المسار /api/v1/.
  • أي مزود جديد يحتاج سجل إذن منفصلًا وقابلًا للتعليق أو الإلغاء.
  • لا يحدث اتصال شبكي بمجرد إضافة مزود إلى السجل؛ يلزم تفعيل بيئي صريح.
  • تُقبل HTTPS فقط، مع قائمة نطاقات وحد أقصى للحجم وتحقق اختياري من SHA-256.
  • لا تحتوي الاستجابات العامة على بيانات مستخدمين أو جلسات أو مفاتيح سرية.
  • لا تُنشر الأدوات المحمية أو مفاتيح التصحيح أو محتوى الدورات الخارجية.
